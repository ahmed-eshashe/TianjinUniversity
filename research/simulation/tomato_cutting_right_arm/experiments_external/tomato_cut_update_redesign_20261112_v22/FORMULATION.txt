V22 — REUSABLE CUT GEOMETRY AND OVERLAPPED INDEPENDENT ENVIRONMENTS

Scope
Implementation redesign of the v21 synthetic geometric-cut material prototype. E=100 kPa, nu=0.4, rho=1000 kg/m^3, compressible neo-Hookean stress, selective same-fragment affine extension, exact reduced inertia E^T diag(m) E, mass-orthogonal state transfer, and 12.5 microsecond staggered Verlet integration are unchanged. Runtime support selector remains 1e-8, matching v21's executed default. Historical selector proposals in the inherited contract are not new runtime settings. All existing position, force, volume, energy and velocity limits remain. No physical contact/fracture law is added or replaced.

Convex geometry representation
The starting polyhedron's triangulated boundary is computed with installed reentrant Qhull. Subsequent clipping reuses faces: clip each crossed face, construct the new cap, and integrate the resulting convex boundary. Unchanged parent moments are reused exactly. This computes the same convex material volume and centroid, without calling a new convex hull for each child. It retains every positive-volume region and all four ternary history slots. No sliver deletion, mass floor or material coarsening is used. Ambiguous geometry is rejected.
Redundant coplanar vertices and triangulations can differ from Qhull. Tests require two-way convex containment, equivalent topology, volume/mass, material force, extension matrix and fields; dynamic comparisons evaluate the union of both vertex sets. Native and held-out tests retain the previous tolerances.
Geometry is stored in immutable packed arrays with lazy per-region views. Clones share only immutable geometry; motion and history are independent. Each new cut produces new arrays and invalidates cached operators. This is cached host geometry, not a fully GPU-resident topology solver. Current-region arrays and connectivity are still assembled at each event.

Connections and accounting
Compiled float64 connectivity code reproduces the original compatibility graph and label order. Full-region and root selection retain the same support, fragment compatibility and distance rules. The identity extension shortcut is taken only when the exact original extension is identity. Coupled mass blocks still use the same Cholesky factorization and exact inverse; scalar blocks use the equivalent vectorized square-root operation. Operator caching keys include immutable geometry identity and the support selector; it caches no future cut data.
Fields, volume validation and energy/momentum accounting use compiled scalar arithmetic with no fast-math flags. They avoid repeated temporary matrices and do not discard checks. Reference comparisons bound the resulting roundoff. Compiled geometric updates, transfer, observations and conservation accounting are all included in timing.

GPU storage and dispatch
Pinned host staging and retained rollback arrays replace per-event allocation. Only active array ranges are transferred, and GPU counts gate all active rows/regions. Reserved slots contain no material.
The selected stress, four-row force reduction, exact inverse-inertia and integration kernels are the existing validated sequence. CUDA graph kernel grid sizes are adjusted to active counts with the installed driver's cuGraphExecKernelNodeSetParams API; arguments, kernels, buffers and graph identities remain. Graph execution is instantiated without advancing physics. Capacity failure, invalid replacement and invalid dynamic states are rejected and restored. These driver/Warp bindings are version-specific and require regression checks after an environment upgrade.
Three exploratory kernel variants were rejected: the four-row fused inverse-mass loop and edge-force cache were accurate but slower; the one-warp variant was slower and exceeded the strict pointwise velocity comparison (about 0.343 mm/s versus 0.1 mm/s). They are retained as evidence and are not selected. The selected runtime imports pipeline_gpu -> active_gpu -> cached_gpu, with the original force-reduction/integration order.

Overlapped independent environments
Two groups of eight environments use separate nonblocking CUDA streams. While one group advances, the CPU may prepare a current cut for another group whose previous step has completed. Each group owns its state, history, graph, staging and rollback data. Reading, replacing or starting a second step on an unfinished group is rejected. Results are copied into owned pinned observations, checked, then committed; an invalid group restores its own prior state without changing another group. No policy action or cut history from the future is used at reset. Observed states are not shared between environments.
The complete geometric benchmark includes reset, four current geometry events per body, aggregate preparation, transfers, material stepping, full state observations and conservation checks. In repeated-episode measurements, GPU storage/graphs persist between episodes; reset still overwrites state and geometry and clears cut history. Fresh and reused episodes are compared. First mesh/template preparation and compilation are separately disclosed.

Scope limits
The benchmark is a 60 mm cubic material block on a 6 mm grid, initially 6,000 tetrahedra. It is not an anatomical tomato. Fixed-size pristine geometry may be reused; new size/shape preparation has not been qualified at this rate. The same four-cut/history capacity and earlier restrictions on general partial/curved cuts, root locality, tiny-fragment timesteps and spatial convergence remain.
Physical blade contact, paid fracture, recontact, support/board, robot stepping and policy inference are absent. The 2 N blade force stop and 0.1 mm whole-material penetration limit remain unchanged but are not exercised. A geometric separation is not a paid physical slice. Passing this component speed screen does not pass the actual RL environment gate or experimental validation.
